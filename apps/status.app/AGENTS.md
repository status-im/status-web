# AGENTS.md

Rules for agents working in `apps/status.app`. The root `AGENTS.md` also applies.

## Role

Next.js 15 app behind https://status.app: marketing site, help centre, specs hub, blog and admin
tooling. Port 3001. `content/` is published site content, never code documentation.

## Commands

- `pnpm --filter status.app dev:next`: dev server on :3001.
- `pnpm --filter status.app dev:content`: watch `content/` and rebuild Contentlayer.
- `pnpm --filter status.app build`: lint + blog search index + `next build`.
- `pnpm --filter status.app test`: vitest.
- `pnpm --filter status.app types:check`: Contentlayer build + tsc.
- `pnpm --filter status.app codegen`: regenerate GraphQL types from `codegen.yml`.
- `pnpm --filter status.app sync:cloudinary`: regenerate Cloudinary asset types.
- `pnpm --filter status.app db:generate` / `db:push` / `db:explore` / `db:check`.
- `pnpm --filter status.app env:check`: validate `.env` against the Zod schemas.
- `pnpm --filter status.app lint:remark`: lint `content/help` and `content/legal`.
- `pnpm --filter status.app knip`: detect unused exports and dependencies.

## Rules

- Do not edit `content/**` during docs work: it is site content (help centre, legal, the `specs`
  submodule and the editorial `style-guide`).
- Drizzle owns the schema in `src/server/db/schema/*`. Change the schema, then run
  `pnpm --filter status.app db:generate` to write migrations under `migrations/`. Never hand-edit
  generated migrations; run `db:push` only against a development database.
- GraphQL types under `src/app/(website)/insights/_graphql/generated/` are generated by `codegen`
  from `codegen.yml`. Never hand-edit them; regenerate instead.
- Cloudinary asset types in `src/app/_components/assets/types.ts` are generated by
  `sync:cloudinary`. Never hand-edit them; regenerate instead.
- Markdown in `content/` must pass `lint:remark` (remark-lint and prettier presets). Run it before
  finishing content-adjacent changes.
- `env:check` runs before builds and via lint-staged on `.env` and the env schema files. Keep the
  Zod schemas in `src/config/env.{server,client}.mjs` in sync with `.env.example`.

## Gotchas

- `.contentlayer/` and `.contentlayer2/` are generated and gitignored; `predev:next`, `prelint` and
  `build` regenerate them.
- `content/specs` is a git submodule. A build host without it fails the build on purpose; see
  `scripts/ensure-specs-content.mjs` and [self-hosting](docs/self-hosting.md).
- The generated GraphQL files are listed in the `knip.ignore` config in `package.json`; keep those
  entries if you move the generated dir.
- The dev server is `dev:next`, not `dev`; there is no `dev` script in this app.
